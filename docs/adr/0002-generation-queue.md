# ADR 0002. Очередь генерации и провайдер OpenAI

Дата: 18 сентября 2026. Статус: принято, этапы C–D реализованы.

## Решения

- **Очередь в PostgreSQL** (`generation_jobs`, `generation_tasks`), без Redis. Worker берёт задачу
  через `FOR UPDATE SKIP LOCKED` и держит lease (2 мин, heartbeat 30 с); задача с истёкшим lease
  возвращается в `pending` и учитывает уже сделанную попытку. Несколько worker'ов на одной базе
  безопасны; каждый идентифицируется `WORKER_ID` (по умолчанию host+pid).
- **Стадии** `plan → text → review → media-plan → cover → image → audio → assemble`
  (`apps/api/src/worker/stages.ts`). Стадия начинается, когда все задачи предыдущих стадий
  `succeeded`; `text`, `image`, `audio` выполняются параллельно (`GENERATION_CONCURRENCY`).
  `review`, `media-plan`, `assemble` локальные и бесплатные.
- **Провайдер за интерфейсом** (`generation/provider.ts`): `openai` (Responses API со strict
  JSON-схемой, Images API → PNG, audio.speech → WAV) и `fake` (детерминированные тексты,
  синтетические PNG/WAV, инъекция сбоев `input.simulate`). Автотесты и e2e — только на `fake`;
  реальные вызовы делает человек через панель.
- **Схемы ответов модели** (`generation/dto.ts`) — zod → JSON Schema strict. Модель не назначает
  ID, версии, порядок и пути файлов; всё это делает сервер при маппинге в `LessonDocument`.
- **Повторы**: 429/5xx/сеть/`incomplete` → `retry-wait` с backoff `10с·2^n`, до 3 попыток;
  4xx/refusal/невалидная схема/лимит стоимости → `failed` немедленно, job `failed`, остальные
  задачи `cancelled`. Ручной «Повторить шаг» возвращает задачу, отменённых соседей и поздние
  стадии в `pending` с бюджетом в 3 новые попытки.
- **Артефакты по хешу**: `input_hash = sha256({stage, targetId, promptVersion, model, payload})`.
  Перед вызовом провайдера медиа-задача ищет `succeeded` задачу с тем же хешем и переиспользует
  её ассет — повтор одной картинки не перегенерирует остальное. Смена промпта = новый
  `PROMPT_VERSION`, старые артефакты не переиспользуются.
- **Стоимость**: оценка до старта (`generation/estimate.ts`) из ставок в env; фактический usage
  суммируется в `jobs.usage`, при превышении `GENERATION_COST_LIMIT_USD` job останавливается.
  Точных цен провайдера нет — только оценка, так и подписано в UI.
- **Конфликт правок**: `assemble` перезаписывает урок только при совпадении `edit_revision`
  с записанным при прошлой сборке; иначе вариант ИИ сохраняется в `job.output.conflicts`,
  job завершается с предупреждением, кнопка «Применить варианты ИИ» делает замену явно.
- **Генерация никогда не публикует**: результат — черновики `awaiting-review`; выпуск идёт
  обычным путём (validate → план → публикация).
- **Идемпотентность**: `idempotencyKey` генерируется при открытии мастера; повтор запроса
  возвращает тот же job. Один активный job на сет.

## Последствия

- Для генерации нужен отдельный процесс `pnpm dev:worker` (или второй worker на другой
  машине с той же базой и общим `ADMIN_STORAGE_ROOT`).
- Без `OPENAI_API_KEY` при `GENERATION_PROVIDER=openai` мастер отключён с понятным сообщением;
  остальная панель работает. `GENERATION_PROVIDER=fake` даёт полный сценарий без ключа.
- Уроки генерируются с id `<courseId>-NN`; повторная генерация того же сета перезаписывает
  нетронутые уроки и не трогает изменённые вручную.
- Не в объёме: SSE вместо polling, отмена уже идущего внешнего запроса, редакторская
  проверка произношения, бэкапы и восстановление (этап E).
