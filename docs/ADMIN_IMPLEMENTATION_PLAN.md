# План реализации веб-панели разработчика

Статус: техническое задание для следующего агента. Панель ещё не реализована. План учитывает текущую главную страницу с карточками сетов и каталог ревизии 3. Перед началом проверить фактическое состояние файлов: номера ревизий могут вырасти.

## 1. Цель и обязательные сценарии

Администратор управляет языками, сетами, уроками, заданиями и медиа через веб-интерфейс. Изменения после публикации приходят в уже установленное приложение Android/iOS через API. Аудитория — дети 6–9 лет; язык интерфейса и объяснений — русский, изучаемый язык выбирается в панели. Первым наполнен английский.

Основной сценарий создания:

1. Выбрать изучаемый язык.
2. Выбрать тему из списка или ввести свою.
3. Указать **общее количество заданий в сете**, а не количество уроков.
4. Увидеть предлагаемое распределение по урокам и состав генерируемых материалов.
5. Нажать «Создать черновик с ИИ».
6. Дождаться учебного плана, заданий, обложки, иллюстраций и озвучки; наблюдать состояния отдельных шагов.
7. Просмотреть и при необходимости исправить каждый урок, заменить отдельную картинку или перегенерировать задание.
8. Пройти предварительную проверку, увидеть изменения выпуска и отдельно нажать «Опубликовать».
9. В приложении обновить каталог: появятся язык/сет/уроки/обложка, прогресс останется сохранённым.

Также обязательны ручное создание и редактирование: отсутствие ключа, лимит расходов или ошибка OpenAI не должны блокировать работу панели. Редактор не должен требовать от администратора ручного написания JSON.

Терминология: **сет = `course`** в существующем коде; сет содержит уроки, урок — задания (`exercises`). Не создавать вторую конкурирующую сущность `set` рядом с `course`.

## 3. Контракт главной страницы — сохранять совместимость

Схема каталога остаётся `schemaVersion: 2`; новый выпуск увеличивает `revision`. Дополнительные поля главной необязательны, старые каталоги валидны.

```ts
type CourseCard = {
  id: string;
  language: string;
  title: string;
  description?: string; // до 200 символов
  cover?: Media; // полный PNG, kind=image, без atlas region
  lessons: LessonReference[]; // минимум один опубликованный урок
};
type CoursePreview = {
  id: string;
  language: string;
  title: string; // до 100 символов
  description: string;
  cover: Media;
};
// catalog.courses: CourseCard[]
// catalog.previews?: CoursePreview[]
```

- Порядок `catalog.courses`, отфильтрованный по языку, задаёт последовательность сетов. В панели можно хранить `position`; сборщик выпуска сортирует массив.
- `catalog.previews` — публичные анонсы «Скоро», **не черновики** и не доступные уроки. Они показываются после опубликованных сетов, не участвуют в блокировках и прогрессе.
- ID анонса и опубликованного сета не могут одновременно присутствовать в одном каталоге. При выпуске `en-underwater` убрать его из `previews`, добавить в `courses`, сохранить ID.
- Новый опубликованный сет и его обложка не должны требовать нового `require()` в мобильном коде. `coverSource` уже поддерживает путь медиа с API; локальные изображения нужны только для встроенного стартового комплекта.
- Обложка по пути `/v1/media/<sha256>.png`; издатель проверяет её так же, как картинки заданий. Отсутствие обложки допускается: приложение рисует лесную иллюстрацию. Для нового сета в панели требовать осмысленную обложку до публикации.
- Прогресс карточки считается по завершённым урокам, звёзды — по лучшим результатам. В макете были демонстрационные жизни, серии и дневная цель: их не добавлять как фиктивные числа. Реальные ежедневные цели — отдельная задача.

### Открытие и сохранение прогресса

Первый сет каждого языка открыт. Следующий открывается после всех уроков предыдущих сетов; достаточно завершения, три звезды не обязательны. Анонсы всегда «Скоро», даже когда предыдущий сет пройден: обещать доступ после леса нельзя, пока новых уроков нет.

В `LearningState` добавлены необязательные `unlockedCourseIds` и `completedCourseIds`. Старые сохранения без этих полей принимаются; `reconcileCourseAccess` восстанавливает доступ из результатов и текущей сессии и запоминает заработанное открытие. Перестановка сетов и добавление урока не отнимают доступ. Пройденный ранее сет сохраняет отметку завершения, а дробь/проценты отражают текущий состав уроков — после добавления урока они могут быть ниже 100%. Панель должна объяснять это при публикации изменения состава.

Не менять стабильные ID опубликованных сущностей. Новая версия задания внутри урока увеличивает `lesson.version`; название не является идентификатором. Начатая сессия содержит полный снимок урока, её нельзя подменять свежей версией. Награды выдаются по ID урока, не по номеру версии. При будущих аккаунтах эти правила и заработанный доступ перенести на сервер.

## 4. Архитектура панели и хранения

Предлагаемое решение для реализации: React + TypeScript + Vite в `apps/admin`, существующий Fastify как единственный backend, PostgreSQL для редакторских данных, сессий, фоновых работ и журнала изменений. UI панели отдельный от детского интерфейса; общие схемы и учебная логика — из workspace packages. Выбор ORM зафиксировать коротким ADR перед первой миграцией; не менять публичный формат ради удобства ORM.

Для MVP достаточно одного worker-процесса с очередью в PostgreSQL, без обязательного Redis. Очередь должна переживать перезапуск. JSON-файл, React state и `setTimeout` не заменяют постоянное хранилище фоновой задачи.

Разделить два источника данных:

- **Редакторское хранилище:** изменяемые черновики, настройки языков, задания генерации, ревью, служебные поля.
- **Публичное хранилище выпусков:** только проверенные неизменяемые JSON-пакеты/медиа и текущий каталог. На первом этапе можно сохранить существующий `content/store` и общий файловый том для API/worker.

DB — источник истины для редактора, `content/store/catalog.json` — указатель опубликованного выпуска. Не читать черновики из публичных GET. Для нескольких серверов позже нужен общий объектный storage и единый механизм переключения указателя; локальный lock-файл не защищает разные машины.

### Сущности и ограничения

| Сущность         | Основные поля / правила                                                                                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AdminUser`      | id, нормализованный login, passwordHash, role=admin, disabledAt; создание первого пользователя CLI, без публичной регистрации                                                    |
| `AdminSession`   | hash токена, userId, expiresAt, revokedAt; токен только в HttpOnly-cookie                                                                                                        |
| `Language`       | стабильный code, title, direction, locale для озвучки, status=draft/active/archived, position                                                                                    |
| `Topic`          | id, title, curriculumBrief, styleBrief; пресеты необязательны, свободный ввод разрешён                                                                                           |
| `CourseDraft`    | стабильный courseId, languageCode, topic, title, description, coverAssetId, position, visibility=draft/preview/published/archived, editRevision, publishedRevision, review state |
| `LessonDraft`    | lessonId, courseId, position, title, presentation, words/media/exercises в проверяемом документе, editRevision, lastPublishedVersion                                             |
| `Asset`          | id, sha256, MIME, byteSize, dimensions/duration, storageKey, status, provenance, transcript/alt description, generationTaskId                                                    |
| `GenerationJob`  | id, courseId, immutable input snapshot, model config, promptVersion, status, timestamps, requestedBy, idempotencyKey, usage/cost data                                            |
| `GenerationTask` | jobId, stage, targetId, inputHash, outputRef, attempts, status, leaseOwner, leaseUntil, nextAttemptAt, providerRequestId, lastError                                              |
| `Publication`    | id, baseCatalogRevision, targetRevision, releaseHash, draft snapshot, status, actor, timestamps, error; unique revision/idempotency key                                          |
| `AuditEvent`     | actor, entity, action, timestamp, revision references; без ключей, cookie, паролей и детских данных                                                                              |

Уникальные индексы на ID/code, `courseId + position` и `lessonId + publishedVersion` по месту. Редактирование с optimistic concurrency: UI отправляет `editRevision`, устаревший запрос получает 409 и понятное предложение обновить черновик. Два открытых браузера не должны молча затирать изменения.

Начальный импорт — отдельная идемпотентная команда, читает **текущий опубликованный каталог и его пакеты**, а не обязательно `seed.json`: рабочий каталог мог быть расширен вручную. Импортировать анонсы, ссылки на медиа и опубликованные версии; сохранить старые файлы. Перед миграцией сделать резервную копию. Не запускать seed поверх существующего редакторского хранилища при каждом старте.

## 5. Страницы и действия

### Вход

Login/password, ошибка без раскрытия существования аккаунта, выход, истечение сессии. После входа возвращать на исходный URL. При истечении сессии редактор сохраняет локальный незаписанный ввод и предлагает войти; сервер отклоняет запись без роли.

### Языки

Список, активность, число сетов, создание/редактирование. Поля: код, название, направление, locale озвучки, порядок. Код соответствует текущему regex ID (нижний регистр; например `pt-br`), уникален и неизменяем после публикации. Язык можно создать без уроков; детское приложение уже умеет показывать пустое состояние. Активация/скрытие становится публичной только в новом выпуске.

Архивирование языка исключает его и его карточки из нового каталога, не удаляет старые версии уроков, медиа и прогресс. Для первого выпуска панели не вводить физическое удаление опубликованного контента. Проверить возврат языка после архива и незавершённую сессию скрытого языка.

### Сеты

Фильтр по языку, статусы, сортировка, создание вручную или с ИИ. Поля: тема, название, описание, обложка, порядок, анонс/черновик. Показать предпросмотр карточки и последовательность открывания. Перестановка сначала сохраняется в черновике; публикация показывает diff. Все тексты редактируются, обложку можно загрузить самостоятельно.

### Мастер генерации

Основные три поля — язык, тема, общее число заданий. Предлагаемые лимиты MVP: 6–60 заданий на запрос; по умолчанию 6 заданий на урок, максимум 30 в одном пакете по контракту. Например 24 → 4×6, 25 → 6+6+6+7. Показать распределение до отправки; не создавать одно задание в отдельном финальном уроке. Лимиты настраиваются сервером, это продуктовые настройки, а не ограничения провайдера.

Дополнительно раскрываемый блок: уровень beginner, возраст 6–9, целевые слова, число уроков, смесь трёх механик, стиль иллюстраций. Перед стартом показать число ожидаемых картинок и аудиофайлов, установленный лимит расходов. Все значения перепроверяются сервером.

### Редактор урока

Список уроков с целями, количеством заданий и готовностью медиа. Внутри — упорядоченные задания, добавление/дублирование/удаление/перестановка, выбор механики, форма её полей. Дублированное задание получает новый ID; изменение существующего сохраняет его идентичность в черновике.

| Механика            | Поля и проверка                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `listen-and-select` | правильное слово, 2–6 уникальных вариантов с правильным среди них, текст вопроса, подсказка, изображения и аудио               |
| `match-pairs`       | 2–4 уникальных слова, перестановка тех же картинок, вопрос и подсказка                                                         |
| `build-word`        | слово, отдельные тайлы с уникальными ID, буквы и отвлекающие тайлы; слово должно собираться без повторного использования тайла |

Справочник слов урока содержит `text`, `spelling`, `translation`, `imageId`, `audioId`. Не создавать картинки ответов внутри текста вопроса. Правильный ответ и подсказки сохраняются в пакете для локальной проверки без сети. Редактор показывает ошибки по конкретному полю/заданию и объясняет отсутствующие связи медиа.

### Предпросмотр

Карточка сета и весь игровой урок: ответы, ошибки, повторение, награда, прослушивание обычное/замедленное. Использовать `learning-core` и те же схемы; предпросмотр имеет изолированную память и не изменяет детский прогресс. Начать с web-рендера существующих механик; при вынесении общей UI-библиотеки не ломать мобильные импорты и bundler. Не встраивать публичный урок по ID как предпросмотр черновика: пакет ещё не опубликован.

### Медиа, задания генерации, выпуски

Библиотека файлов с привязками, источником и прослушиванием; экран работ с прогрессом шагов, ошибкой и повтором выбранного шага; история выпусков с автором, diff и действием восстановления. Не показывать пользователю панели стек/ключ провайдера. Техническая диагностика — в серверных логах с request ID.

## 6. Предлагаемые HTTP-контракты

Это новые маршруты для реализации, сейчас их нет. Общий namespace `/v1/admin`; публичные GET оставить совместимыми.

| Метод / путь                                            | Результат                                                                          |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `POST /auth/login`, `POST /auth/logout`, `GET /auth/me` | Вход/выход/текущий администратор                                                   |
| `GET, POST /languages`; `PATCH /languages/:code`        | Список, создание, изменения/архив                                                  |
| `GET, POST /courses`; `GET, PATCH /courses/:id`         | Сеты с фильтрами, создание, редактор                                               |
| `PUT /courses/:id/lesson-order`                         | Атомарный порядок ID уроков с `editRevision`                                       |
| `POST /courses/:id/lessons`; `GET, PATCH /lessons/:id`  | Ручное создание/редактирование документа                                           |
| `POST /assets`                                          | Ограниченная загрузка PNG/WAV; нормализация, SHA-256, метаданные                   |
| `GET /assets/:id`                                       | Авторизованное чтение чернового файла/метаданных                                   |
| `POST /courses/:id/generations`                         | 202 и jobId; повтор с тем же idempotency key не запускает вторую работу            |
| `GET /generations/:id`                                  | Статусы шагов, прогресс, разрешённые действия                                      |
| `POST /generations/:id/tasks/:taskId/retry`             | Повтор выбранного шага с новой попыткой и лимитами                                 |
| `POST /generations/:id/cancel`                          | Запрет запуска следующих шагов; текущий внешний вызов может уже расходовать бюджет |
| `POST /courses/:id/validate`                            | Отчёт о схемах, решаемости, файлах, ревью и совместимости                          |
| `POST /publication-plans`                               | Подготовленный неизменяемый snapshot, diff, хеш, baseRevision                      |
| `POST /publications`                                    | Публикация конкретного проверенного snapshot/хеша, 202 + publicationId             |
| `GET /publications`, `GET /publications/:id`            | История и состояние публикации                                                     |
| `POST /publication-plans/restore`                       | План нового выпуска на основе старого; затем обычная публикация                    |

Выдавать структурированные ошибки `{code, message, fieldErrors?, requestId}`. 400 — форма/схема; 401/403 — доступ; 404 — нет сущности; 409 — конфликт редактирования/базовой ревизии; 413 — размер; 422 — непубликуемый документ; 429 — лимит. Конкретное распределение закрепить общим контрактом и тестами.

Листинги с пагинацией; параметры сортировки/фильтров ограничены белым списком. Для прогресса MVP достаточно polling с увеличением интервала в фоновой вкладке; SSE можно добавить позже. URL медиа не должен позволять обход путей или чтение произвольных серверных файлов.

## 7. Генерация OpenAI — только на сервере

Это несколько этапов одной фоновой работы, а не один длинный HTTP-запрос из браузера. Ключ хранится в серверном `.env`, никогда в `VITE_*`, `EXPO_PUBLIC_*`, HTML, bundle или публичном API. Данные детей не нужны для подготовки учебного контента и не отправляются провайдеру.

1. **План:** нормализовать вход; сформировать цели каждого урока, последовательность, словарь и распределение заданий. Включить контекст уже существующих уроков темы для уменьшения повторов.
2. **Текст:** получить structured output по ограниченному DTO генератора; преобразовать в собственные модели и проверить Zod. ID, пути файлов, версии и порядок назначает сервер, не модель.
3. **Проверка материала:** возраст, язык, переводы, число заданий, решаемость, разные цели уроков, отсутствие случайно одинаковых списков заданий. Совпадение учебных слов между введением и повторением допустимо; полное копирование урока — нет. При провале ограниченное исправление, затем понятная ошибка и ручное редактирование.
4. **Медиа-план:** составить список уникальных иллюстраций и аудиофраз. Повторно используемое слово не требует новой картинки в каждом задании. Обложка — отдельный ресурс, не скриншот UI и не коллаж с кнопками.
5. **Обложка и иллюстрации:** отдельные image-generation вызовы с общим style brief и утверждённым образом Тима. Детские дружелюбные иллюстрации; картинки вариантов различимы; обложка без встроенного текста, поскольку название рисует приложение. Сохранить выбранный результат на своём storage.
6. **Озвучка:** отдельные аудиофайлы по проверенным текстам, соответствующим изучаемому языку. Привязать transcript, locale, voice/model config. Проверить длительность/тишину/формат; дать редактору прослушать. Не использовать голосовое клонирование для этой задачи.
7. **Сборка:** связать медиа, прогнать `courseLessonSchema` и пакетные проверки; сохранить готовый **черновик**, состояние `awaiting-review`. Генерация никогда не публикует автоматически.

Официальные ориентиры: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Image generation](https://developers.openai.com/api/docs/guides/image-generation). Перед реализацией адаптера проверить актуальные модели, SDK, лимиты и формат аудио в официальной документации. Названия моделей и цены не зашивать в UI: `OPENAI_TEXT_MODEL`, `OPENAI_IMAGE_MODEL`, `OPENAI_AUDIO_MODEL` в серверной конфигурации. Формальная валидность structured output не доказывает правильность учебного материала; refusal, неполный ответ и таймаут обрабатываются отдельно.

### Надёжность worker

- Job: `queued → running → awaiting-review | failed | cancelled`. Task: `pending → running → succeeded | retry-wait | failed | cancelled`. Состояние публикации отдельное от генерации.
- Worker берёт lease задачи транзакционно; heartbeat и срок lease позволяют восстановление после падения. Перезапуск не создаёт второй job и не теряет успешные результаты.
- Ограничить параллелизм, число попыток и верхнюю стоимость работы. Для 429/временных ошибок — ограниченные повторы с backoff; ошибки схемы/авторизации не повторять бесконечно.
- Ключ артефакта включает snapshot ввода, модель, версию prompt, целевой объект. Повтор изображения не перегенерирует тексты и уже одобренные материалы.
- Внешний запрос мог успешно выполниться до сетевого обрыва. Не обещать exactly-once оплату провайдеру: хранить request ID/результат, восстанавливать где API позволяет, иначе показывать неопределённую попытку и учитывать риск повторного расхода.
- При завершении задачи сверять `editRevision`: ИИ не должен перезаписать текст, который администратор исправил во время генерации. Сохранить новый вариант для сравнения.
- Отмена останавливает новые задачи; поздний ответ сохраняется как артефакт, но не меняет опубликованный контент.
- Fake-провайдер для тестов с фиксированными ответами, задержкой, отказом и ошибками. Реальные платные вызовы не входят в автоматические тесты.

## 8. Медиа и безопасность

Текущий контракт поддерживает PNG и WAV; не отдавать моделиные WebP/JPEG/MP3 под чужим расширением. Если провайдер вернул другой формат, декодировать и конвертировать серверным инструментом или отдельно расширить контракт и мобильный загрузчик с проверкой совместимости. SHA-256 считать **после** нормализации файла. Проверять сигнатуру, фактический формат, размеры/длительность и лимит байтов; не доверять клиентским filename/MIME.

Держать черновые файлы вне публичного `content/store/media`. Подпись пути SHA-256 — идентичность, не механизм авторизации. До публикации файлы доступны через защищённые admin-маршруты; после копирования в публичный store считаются публичными. Запретить серверное скачивание произвольных URL из формы: использовать загрузку файла или доверенный адаптер провайдера.

Происхождение ресурсов записывать в Asset: загрузил администратор / сгенерировано, promptVersion, модель, дата, source reference. Два текущих изображения предоставлены пользователем в `../main_s`, см. `content/assets-manifest/demo.json`; их не нужно генерировать заново.

Обязательная защита до появления HTTP-записи:

- Проверка admin-сессии и роли на сервере для **всех** маршрутов черновиков, jobs, uploads, preview и публикации.
- Хеширование паролей предназначенной для этого библиотекой, rate limit входа, серверное истечение/отзыв сессий; в production cookie Secure + HttpOnly + SameSite.
- Сейчас API выставляет `Access-Control-Allow-Origin: *` глобально. Перенести это только на публичные GET. Admin UI предпочтительно обслуживать с того же origin; при отдельном dev origin — точный allowlist и credentials, без `*`.
- Защита CSRF для cookie-auth записей, проверка Origin, запрет изменения через GET; CORS не заменяет авторизацию.
- Ограничение тела, размеров upload, числа заданий, параллельных генераций; секреты не логировать. Отображать пользовательский текст как текст, без выполнения HTML или кода модели.
- Не хранить OpenAI-ключ в базе вместе с черновиком; bootstrap credentials не включать в репозиторий и не передавать аргументом shell с сохранением в истории.

## 9. Публикация, конфликт и восстановление

1. Выбрать конкретные сохранённые черновики. Зафиксировать их `editRevision` и `baseCatalogRevision`.
2. Построить полный будущий выпуск: текущие опубликованные пакеты плюс изменения, активные языки, порядок сетов и публичные анонсы. Частичный черновик не должен удалить все остальные сеты.
3. Неизменённые уроки сохранить с той же версией; изменённые — с увеличенной; новый урок начинает с 1. Для изменения только обложки/названия сета достаточно новой ревизии каталога.
4. Проверить схемы, уникальность ID, ссылки, количество/типы упражнений, решаемость, полноту файлов и редакторское подтверждение. Повторить проверку на сервере независимо от результатов UI.
5. Подготовить нормализованные файлы в публичном media store, записать все пакеты и snapshot нового каталога. Номер ревизии назначить под общей блокировкой с повторной проверкой baseRevision.
6. Переиспользовать `publishRelease`, переключающий текущий каталог последним действием. Не заменять неизменяемые файлы на месте. Весь путь записи, включая CLI, должен учитывать одну и ту же блокировку.
7. Зафиксировать publication result и audit. При падении между переключением файла и DB commit сравнить текущий catalog revision/hash с подготовленным Publication и завершить восстановление, а не публиковать вторично.

Состояния публикации: `prepared → publishing → published | failed`, плюс процедура recovery для застрявших `publishing`. На первом этапе API/worker/CLI работают на одном общем томе. Текущий `.publish.lock` может остаться после жёсткого падения: реализовать восстановление с проверкой владельца/lease и отсутствия действующего писателя; не удалять lock безусловно по таймауту.

Откат — **новый** выпуск с увеличенной ревизией, ссылающийся на старые проверенные версии пакетов. Не уменьшать `catalog.revision`, не перезаписывать историю. Старые версии и медиа нужны активным/офлайн-сессиям; их garbage collection отложить до явной retention-политики и проверки ссылок.

Публичный API не принимает от мобильного клиента команды публикации. Редактор может изменять будущий контент во время проверки выпуска, но уже подготовленный snapshot остаётся неизменным; новые правки попадут в следующий план.

## 10. Совместимость и офлайн

Новые языки/задания работают без обновления приложения только в пределах реализованных механик, текста, шрифтов и медиа-форматов. Новый интерактивный тип требует нового клиента. `requiredTypes` и `schemaVersion` проверять до публикации; несовместимый выпуск не выдавать старому клиенту. Если появятся версии протокола, вести отдельные совместимые представления каталога, не просто повышать число и ломать старую выдачу.

`direction` уже есть в языке, но полноценная поддержка RTL и сложных письменностей **не доказана**. Перед публичной активацией нового языка проверить шрифты, направление, нормализацию, разбиение на буквы и озвучку. Текущее `build-word` проверяет кодовые точки NFC, что не универсально для графем; для неподдерживаемой письменности адаптировать механику и тесты, не обещать универсальность из-за одного поля locale.

Автопредзагрузка **текущего + трёх следующих** уроков остаётся отдельным обязательным этапом. Панель должна уже выпускать полные автономные пакеты: аудио, изображения, ответы и подсказки, без обращения к OpenAI при прохождении. Карточка/анонс не означает «скачано». Сейчас встроенные картинки доступны локально, новые серверные обложки имеют визуальный fallback; гарантированный офлайн-кэш обложек предстоит вместе с менеджером загрузок.

Будущий менеджер предзагрузки следует порядку языка/сетов, проверяет все файлы, защищает активный пакет от очистки, сохраняет результаты и не отменяет условия открытия. Аккаунты/серверная синхронизация прогресса не блокируют первый выпуск админки и не входят скрыто в его объём.

## 11. Этапы реализации и критерии приёмки

### A. Основа и защита

Создать `apps/admin` и workspace-скрипт `dev:admin`; миграции DB, bootstrap admin, сессии, CSRF/CORS, защищённый API, audit и импорт текущего контента. Env-примеры без секретов, инструкции запуска API/web/DB/worker. UI работает без OpenAI-ключа.

Готово: вход/выход, неправильный пароль, истёкшая cookie, запрет каждого write/preview endpoint анонимному клиенту, импорт повторно ничего не дублирует, публичный мобильный каталог работает как раньше.

### B. Ручное управление языками и сетами — первый полезный выпуск

Страницы языков и сетов, редактирование уроков трёх типов, upload, черновики, анонсы, reorder, предпросмотр, validation и publication plan. Подключить издатель и историю выпусков. Это приоритетная первая вертикаль; не ждать готовности ИИ для проверки процесса.

Готово: через UI создать второй тестовый язык и сет, добавить урок/картинки/аудио, опубликовать; в уже работающем приложении после обновления появляются карточка и урок, ответы проверяются. Неопубликованный черновик отсутствует в публичных GET; старые результаты и сессия сохранены. Публикация анонса не создаёт ложный доступ к уроку. Превращение анонса в сет не создаёт две карточки.

### C. Устойчивая очередь генерации

Постоянные jobs/tasks, leases, отмена, ограниченные повторы и fake-провайдер. Страница прогресса, ошибки по этапам, повтор одной картинки. Зафиксировать семантику snapshot/конфликтов до реальных внешних запросов.

Готово: перезапуск worker на каждом этапе не теряет задания; повтор клика не создаёт дубль; частично готовый job продолжает работу; ручная правка во время генерации не затирается.

### D. OpenAI и редакторская проверка

Серверные адаптеры текста/изображений/озвучки, версии prompt, лимиты, сохранение артефактов и usage. Мастер «язык → тема → количество», разные цели уроков, review flags, перегенерация выбранного элемента.

Готово: небольшой сет создаётся целиком с медиа; число заданий точно соответствует запросу; минимум один пример каждой выбранной механики решаем; все тексты/медиа можно поправить; отказ или лимит не публикует частичный сет и не блокирует ручную работу.

### E. Выпуск и восстановление

Конфликты двух редакторов/публикаций, recovery DB/files, откат новым выпуском, архивирование/возврат, ограничения совместимости. Резервное копирование DB + медиа + выпусков; проверенное восстановление в отдельное окружение. Не разворачивать публично и не менять production-данные как часть локального теста.

Готово: один завершённый сценарий от пустого языка до карточки в мобильном приложении; проверены обрыв сети, устаревший plan, падение worker, missing media и неизменяемость версии. Документация совпадает с командами и состоянием кода.

## 14. Короткое поручение следующему агенту

> Реализуй админ-панель по `docs/ADMIN_IMPLEMENTATION_PLAN.md`, начиная с этапов A–B: защищённый вход, постоянное хранение, импорт текущего каталога, ручное добавление языков/сетов/уроков/медиа, предпросмотр и публикация. Сохрани контракт главной страницы, ID, прогресс и версии уроков. Сначала доведи до работающего сценарий «новый язык и сет в панели → обновить каталог в приложении → пройти урок». Затем переходи к устойчивым jobs и OpenAI по этапам C–E. Не генерируй дублирующиеся уроки, не публикуй результаты ИИ автоматически и не добавляй ключ в клиент. Подтверди результат тестами и обнови документацию. Полная предзагрузка трёх следующих уроков остаётся отдельным этапом. Аккаунты учеников относятся к этапу 4 ROADMAP.md: один ребёнок — один аккаунт со своей почтой, без семейных профилей и родительских функций.
