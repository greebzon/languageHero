# Контент и публикация

На этапе 3 контент публикуется локальной командой. Веб-панель появится на этапе 5 и будет использовать эти же схемы и правила версий. Сейчас HTTP API доступен только для чтения опубликованного учебного материала; аккаунтов, закрытых платных курсов и серверных наград пока нет.

## Первая тема

В `content/seed.json` находятся пять уроков: «Лесные друзья» (6 заданий), «Кто спрятался?» (4), «Найди пары» (3), «Собери слова» (4), «Праздник в лесу» (6). Тема закрепляет четыре слова: fox — лиса, bear — медведь, rabbit — кролик, owl — сова. Ошибочное задание добавляется в конец текущего урока один раз; для завершения нужен правильный ответ и при повторении.

Выпуск каталога 2 обновляет только «Праздник в лесу» до версии 2. «Лесные друзья» — узнавание животных на слух; «Праздник» — отдельный сюжет с проверкой списка гостей, раздачей приглашений и четырьмя словами с лишними буквами. У него собственные вступление и финал (`presentation` в пакете). Старые версии и уже заработанные награды сохранены. Открытый незавершённый урок доигрывается на прежней версии. Если же выйти на карту и начать урок снова, он начнётся заново на новой версии (`resumableSession`): так исправленные картинки и звук доходят до ребёнка, не дожидаясь, пока он закончит старый снимок.

Первый выпуск уже находится в `content/store/`. Начальный комплект также встроен в приложение как резерв на случай недоступного API. `scripts/create-seed.py` воспроизводит исходный JSON и копирует существующие медиа; эту команду не нужно выполнять при обычном запуске.

## Добавление урока без обновления приложения

1. Скопировать `content/seed.json` в файл нового выпуска, например `content/release-2.json`.
2. Увеличить `catalog.revision`. Для нового урока добавить пакет с новым `id` и `version: 1` в `lessons`, а ссылку на него — в `catalog.courses[].lessons`. Порядок ссылок задаёт учебную последовательность. Для изменения существующего урока увеличить его `version` и версию ссылки. Остальные опубликованные уроки оставить в выпуске.
3. Использовать механики `listen-and-select`, `match-pairs`, `build-word`, `choice` (см. «Механики заданий»). Схемы и ограничения находятся в `packages/contracts/src/mechanics/`. Количество заданий, название и `requiredTypes` в каталоге должны совпадать с пакетом.
4. Для новых изображений PNG и звуков WAV вычислить SHA-256 файла, скопировать файл в `content/store/media/<sha256>.png` или `.wav`, указать `/v1/media/<sha256>.<ext>` в `media[].path`. `region` позволяет брать ячейку из атласа изображений; для отдельного изображения поле не нужно. Медиа связаны со словами через идентификаторы, а не через код приложения.
5. Выполнить публикацию:

```powershell
pnpm content:publish content/release-2.json
```

6. В уже открытом приложении нажать «Обновить». Каталог также проверяется при запуске, возврате в приложение и восстановлении подключения. Сервер перезапускать не нужно.

Для нового языка добавить запись в `catalog.languages` и курс с соответствующим `language`; пакеты уроков должны содержать тот же код. Список языков строится из каталога. Новая механика требует обновления приложения (приложение без неё такие уроки просто не получает), обычные уроки на существующих механиках и новые варианты «Выбора» — нет. Для языка со специфической сегментацией букв нужно проверять упражнения сборки слова: текущий движок использует Unicode code points и NFC.

Публикация сначала проверяет все пакеты, возможность собрать слова, ссылки на картинки/звук, сигнатуры и SHA-256 файлов. Затем записывает неизменяемые версии уроков и снимок каталога. Замена `catalog.json` происходит последней, через переименование временного файла. Ошибочная публикация оставляет прежний каталог действующим. Нельзя редактировать `content/store/lessons` вручную; повторная запись той же версии с другими данными отклоняется. Если процесс аварийно завершился, перед удалением оставшегося `.publish.lock` убедиться, что другой процесс публикации не работает.

Откат выполняется новым выпуском с большей ревизией каталога и ссылками на нужные старые версии уроков. Исключение языка/курса из нового каталога скрывает его для нового старта. Ранее начатый урок можно закончить на сохранённом пакете; прогресс сохраняется. Старые версии пакетов и медиа пока не удаляются автоматически.

## Механики заданий

Механика описывается один раз на каждом слое, в файле с именем типа:

| Слой       | Где                                             | Что                                                                                                                                                                                 |
| ---------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Данные     | `packages/contracts/src/mechanics/<тип>.ts`     | строгая схема задания, мягкая черновая схема, форма ответа, проверки ссылок и решаемости (`validate`), какие слова задание тренирует (`words`), замена ссылок на слова (`mapWords`) |
| Правила    | `packages/learning-core/src/mechanics/<тип>.ts` | `assess`: верно, неверно или ответ не той формы                                                                                                                                     |
| Приложение | `apps/mobile/src/mechanics/<тип>.tsx`           | `View` и необязательный `Hint` под подсказкой                                                                                                                                       |
| Панель     | `apps/admin/src/mechanics/<тип>.tsx`            | название, пустое задание, форма редактора, предпросмотр                                                                                                                             |
| Генерация  | `apps/api/src/generation/mechanics/<тип>.ts`    | описание и правила полей для модели, сборка задания из ответа модели, пересборка при переводе клона, ответ fake-провайдера                                                          |

Каждый слой собирает модули в `index.ts` в объект с типом `{ [K in ExerciseType]: … }`. Новая механика начинается с `contracts/src/mechanics/index.ts` (одна строка в `courseExerciseSchema`, `draftExerciseSchema`, при новой форме ответа — в `answerSchema`, и запись в реестре); после этого `pnpm typecheck` показывает каждый слой, где модуля ещё нет, и строку `common.mechanics.<тип>` в текстах приложения. Ответы не помечены типом: механики могут делить форму ответа (`choice` использует `{choiceId}`), а сохранённые сессии остаются действительными. В модуле правил есть `solve` — эталонный ответ, через `solveExercise` его используют тесты. E2E-хелпер `solve` в `tests/e2e/helpers.ts` написан как `switch` с проверкой `never`, поэтому для новой механики tsc попросит и способ пройти её в браузере.

**«Выбор» (`choice`)** — одна механика для целого семейства заданий. `show` — из чего состоит вопрос (до трёх частей: `audio`, `image`, `text`, `translation` слова урока), `as` — как выглядят варианты (`image`, `text`, `letter`, `yes-no`), `options` и `answerId` — варианты и правильный. Проверки схемы: варианты-картинки и варианты-слова ссылаются на разные слова урока, и правильный — то слово, о котором вопрос; буквы не повторяются; у «да / нет» ровно варианты `yes`/`no`, минимум две части вопроса, и ответ «да» — тогда и только тогда, когда все части про одно слово. Новая комбинация `show`/`as` — это данные: её можно собрать в панели и опубликовать без обновления приложения. Готовые комбинации (`CHOICE_PRESETS`):

| Пресет         | Вопрос           | Варианты | Генерация                                         |
| -------------- | ---------------- | -------- | ------------------------------------------------- |
| `find-picture` | слово            | картинки | да                                                |
| `name-picture` | картинка         | слова    | да                                                |
| `translate`    | перевод          | слова    | да                                                |
| `is-it`        | картинка + слово | да / нет | да                                                |
| `first-sound`  | картинка + звук  | буквы    | да                                                |
| `odd-one-out`  | —                | картинки | нет, только вручную (нужны слова из разных групп) |

При генерации модель выбирает пресет (`variant`) и слово, а варианты строит сервер: «да» или «нет» в `is-it` решает детерминированная монетка, буквы `first-sound` — первая буква слова и отвлекающие. При переводе клона буквы `first-sound` пересобираются из нового написания.

**«Собери фразу» (`build-sentence`)**: фраза из плиток-слов. `tokens` — плитки (`text`, у слов урока `wordId`, тогда на плитке картинка слова), `answer` — правильный порядок слов, `alternatives` — другие верные порядки, `audioId` — озвучка всей фразы (отдельное медиа урока). Плитки сравниваются по тексту без учёта регистра, поэтому две плитки «the» взаимозаменяемы. Схема проверяет, что из плиток собирается ответ и каждая альтернатива. Ответ — `{ tileIds }`, как у сборки слова. Первое слово фразы хранится с маленькой буквы (кроме однобуквенных, «I»), чтобы заглавная не подсказывала начало; приложение само пишет собранную фразу с заглавной.

**«Мемори» (`memory`)**: карточки рубашкой вверх, на каждое слово карточка с картинкой и карточка со словом (`order` — порядок на столе, id карточек `<слово>-image`/`<слово>-text`). Ребёнок открывает по две; совпавшие остаются открытыми и попадают в ответ `{ pairs }`, поэтому ответ полон, только когда найдены все пары. Это игровая пауза без неверных ответов. Для 6–7 лет — не больше 3 пар.

**«Поймай слово» (`catch-word`)**: раунды (`rounds: [{ wordId, choices }]`). Звучит слово, по экрану плавают пузыри с картинками `choices`, нужно лопнуть нужный. Ответ — все нажатия по порядку (`{ taps }`). Сервер проигрывает их заново (`catchProgress`): нажатие на пузырь не из текущего раунда или после конца игры делает ответ недействительным, не больше `CATCH_MISSES` (1) промахов — верно, больше — неверно, и задание вернётся в конце урока. Для 6–7 лет — не больше 3 пузырей в раунде. Генерация строит раунды сама: каждое слово из `choiceKeys` среди двух других слов урока.

**Разнообразие и ритм.** У каждого урока сета свой набор механик (`generation/rhythm.ts`, `lessonMechanics`): окно из 4 запрошенных механик, которое от урока к уроку сдвигается на 2. Соседние уроки отличаются, а сет в целом использует все механики. Если механик 4 или меньше, урок получает все. Набор хранится в плане (`GenerationLessonPlan.mechanics`), его же проверяет review. Порядок заданий сервер расставляет сам (`arrangeExercises`): одна механика (у «Выбора» — один вид) не идёт два раза подряд, трудные задания (`effort` в модуле генерации: 1 — быстрые, 3 — сборка слова и фразы) стоят в середине, урок заканчивается лёгким заданием. Задания перенумеровываются `ex-1…`.

**Урок фраз в конце сета.** Если в механиках генерации есть «Собери фразу» (по умолчанию есть), план добавляет последний урок сета «Собери фразы» (`GenerationLessonPlan.kind = 'sentences'`, `generation/sentences.ts`). Уроки открываются по порядку, поэтому все слова сета к нему уже пройдены. Модель пишет по 4 фразы на возрастную группу (6–7: 2–4 слова, 8–9: 3–6 слов) и один на весь сет короткий список служебных слов (`helperWords`, не больше 12). Сервер принимает фразу, только если каждое её слово — слово сета или служебное, есть хотя бы одно слово сета и фразы не повторяются. Иначе материал уходит на исправление, как остальные уроки. Лишние плитки: 1 для 6–7 лет, 2 для 8–9. Каждая фраза озвучивается отдельной задачей `audio` (`<id урока>/sentence-N`), картинок у фраз нет. Урок фраз не входит в «Всего заданий» запроса. Клон с переводом не переводит фразы, а пишет их заново из переведённых слов.

### Повторение

«Повторение» — урок, который приложение собирает само из слов пройденных уроков текущего языка (`learning-core/src/review.ts`). Генерация для него не нужна, и каждый раз он получается другим. Карточка «Повторение» появляется на главной после первого пройденного урока.

- **Слова.** `reviewPool` берёт каждое слово пройденных уроков один раз (последние 12 уроков; пакеты, которых нет на устройстве, догружаются). `pickReviewWords` выбирает до 6 слов взвешенно по зерну: слова из уроков с меньшим числом звёзд выпадают чаще. Нужно минимум 3 слова.
- **Задания.** `composeReview` строит 8 заданий из картинок и озвучки самих слов: послушай и выбери, найди картинку, пары, «это …?», собери слово, назови картинку, ещё раз послушай, первая буква. Одна механика не идёт дважды подряд. Если задание из этих слов не собрать (например, нет лишних букв), вместо него будет «найди картинку». Тексты урока написаны в коде на ru/en/he, переводы слов берутся из исходных уроков.
- **Проверка на сервере.** Урок не входит в каталог: `id = review`, версия 1. В сессии и попытке лежит `review = { seed, words: [{ lessonId, version, wordId }] }`. Сервер собирает тот же урок из пакетов хранилища и проверяет ответы. Слова допустимы только из уроков, которые ребёнок прошёл, иначе ошибка `review_invalid`.
- **Награды.** Звёзды повторения считаются в общий счёт, как у повторного прохождения урока. XP и монет нет, запись прогресса не создаётся. В `learner_attempts.words` пишется 0, потому что новых слов повторение не даёт. Кнопка «Повторить» на экране результата собирает новое повторение.

### Возраст и подстройка заданий

Ребёнок при регистрации выбирает возраст (6, 7, 8, 9+). Сервер хранит год рождения (`learner_accounts.birth_year`, миграция `0013`), поэтому возраст растёт сам; изменить его можно в профиле. Уроки в пакете одинаковы для всех, подстройка делается при прохождении. `difficultyFor(birthYear)` даёт возрастную группу (`6-7` до семи лет включительно, иначе `8-9`). У каждой механики есть `adapt` в `learning-core/src/mechanics/<тип>.ts`, который облегчает задание в пределах `LIMITS` (`mechanics/adapt.ts`): для 6–7 лет не больше 3 вариантов и 3 пар, одна лишняя буква. Группа 8–9 проходит урок как опубликован. Правильный ответ всегда остаётся.

Группа и зерно (`session.difficulty = { ageBand, seed }`) фиксируются при старте урока и уходят с попыткой. `currentExercise(session)` показывает одно и то же задание приложению, продолженному уроку и повтору на сервере, даже если у сессии сменился `attemptId`. Сервер не сверяет группу с профилем: возраст ребёнок указывает сам, а все ответы по-прежнему перепроверяются (ответ на скрытый вариант отклоняется). В предпросмотре панели есть переключатель «6–7 / 8–9 лет».

Задание с разным содержимым для групп делается полем `ageBands` у любого задания: задание показывается только этим группам (без поля — всем). У каждого варианта свои вопрос и подсказка, поэтому переводы на en/he работают как обычно. Очередь урока строится из заданий группы (`playableIndices`, без возраста — группа 8–9), а схема требует, чтобы у каждой группы было хотя бы одно задание. В каталоге у такого урока есть `exerciseCounts` — число заданий каждой группы (карта уроков показывает число заданий ребёнка). В панели это поле «Для возраста» в форме задания.

**Сложность по успехам.** `LearningState.recent` хранит звёзды последних 5 прохождений (их дописывает `learn()`, поэтому сервер при повторе ведёт ту же историю). `difficultyFor(birthYear, recent)` начинает с возраста и сдвигает группу по последним трём прохождениям: три подряд без ошибок поднимают ребёнка 6–7 лет к заданиям 8–9, три подряд с одной звездой опускают старшего (или ребёнка без возраста) к облегчённым. Смешанная серия ничего не меняет.

Новая механика может добавить свой `adapt`; новое ограничение — поле в `Limits`.

## API

| Метод и путь                                  | Ответ                                                                    |
| --------------------------------------------- | ------------------------------------------------------------------------ |
| `GET /health`                                 | Работоспособность сервера                                                |
| `GET /v1/catalog?schemaVersion=2&mechanics=…` | Языки, курсы, порядок уроков и версии, без заданий и ключей ответов      |
| `GET /v1/lessons/:id/versions/:version`       | Самодостаточный опубликованный пакет, включая локальную проверку ответов |
| `GET /v1/media/:sha256.png` или `.wav`        | Неизменяемый медиафайл                                                   |

Каталог возвращает ETag и поддерживает `If-None-Match`. Пакеты и медиа имеют неизменяемые адреса. Неподдерживаемая версия схемы каталога возвращает 409. `mechanics` — механики, которые умеет показывать приложение (через запятую): уроки с другими механиками в каталог не попадают, сет без уроков тоже; без параметра считаются первые три (`BASE_MECHANICS`). ETag зависит от набора механик. Тот же фильтр применяет `/v1/account/sync` при проверке доступа (поле `mechanics`) и само приложение к сохранённому каталогу (`visibleCatalog`).

Публичный доступ и CORS `*` относятся только к этому учебному контенту. Будущие API профилей и административных действий потребуют отдельной авторизации. Изменять контент через HTTP сейчас невозможно.

## Хранение на устройстве

`lingvohero.learning.v2` содержит настройки, результат каждого урока и один незавершённый урок с полным снимком его версии, очередью повторения и частичным ответом. Старый `lingvohero.demo.v1` переносится при первом запуске новой версии; исходная запись остаётся для восстановления. Награда начисляется один раз на идентификатор урока, обновление версии её не удваивает.

Каталог и полученные пакеты кэшируются отдельно для адреса API. Перед входом в урок загружаются его медиа. Android/iOS используют локальные файлы Expo Asset; открытая веб-страница удерживает загруженные файлы как Blob URL. Перезагрузка страницы без сети и автономный запуск Expo Go не поддерживаются. Надёжное дисковое управление кэшем, лимиты, проверка файлов на клиенте, SQLite, предзагрузка трёх следующих уроков и синхронизация результатов относятся к этапу 6.

Прогресс этого этапа локальный и не является защищённым серверным балансом. Голоса синтезированы для прототипа; редакторская проверка произношения перед публичным выпуском остаётся в плане.

## Карточки миров и передача работы над админкой

В ревизии каталога 3 добавлены описание лесного сета и два анонса с изображениями из `../main_s`. Главная строится из `courses` (опубликованные сеты) и необязательного `previews` (анонсы «Скоро»). Анонсы не содержат уроков и не участвуют в открытии следующих сетов. Публикация готового сета заменяет анонс с тем же ID в одном выпуске.

У курса теперь необязательны `description` и `cover`; у анонса обязательны `id`, `language`, `title`, `description`, `cover`. Обложка — полный PNG через существующий media-контракт, без `region`. Издатель проверяет наличие, хеш и формат обложек перед переключением каталога. Порядок `courses` внутри языка определяет последовательность сетов. Необязательный `unlockStars` у сета — порог звёзд для открытия: звёзды дают за каждое прохождение урока (1–3), повторные тоже считаются, и порог их не тратит. Без порога сет открывается после завершения предыдущего. Открытый сет остаётся открытым навсегда. Новые карточки и серверные изображения загружаются как данные.

Доступ и завершение сетов запоминаются в необязательных полях локального прогресса `unlockedCourseIds` и `completedCourseIds`; сохранения прежнего формата остаются валидными. Уже полученный доступ не отнимается при перестановке сетов или добавлении уроков. Дробь прогресса всегда отражает текущий состав уроков, даже если завершение сета было заработано раньше.

Полное техническое задание для реализации панели: [ADMIN_IMPLEMENTATION_PLAN.md](ADMIN_IMPLEMENTATION_PLAN.md). Веб-панель и генерация OpenAI пока не реализованы. Новые серверные обложки имеют визуальную замену при ошибке загрузки; гарантированный офлайн-кэш обложек и предзагрузка трёх следующих уроков остаются отдельным этапом.

## Публикация через панель

С этапа 5 (A–B) редакторские данные живут в PostgreSQL, а `content/store` остаётся публичным хранилищем выпусков. Панель собирает **полный** выпуск из базы: активные языки, опубликованные сеты (минимум один урок), анонсы с обложкой; черновики не попадают в выпуск. Ссылки в каталоге (`title`, `exerciseCount`, `requiredTypes`) вычисляются из пакета. Версия урока сохраняется, пока не изменился хеш его содержимого, иначе увеличивается; новый урок начинается с 1. Черновые медиа копируются в `content/store/media` по SHA-256 только при публикации, затем вызывается тот же `publishRelease`, что и у `pnpm content:publish`: обе дороги делят `.publish.lock`, ревизия каталога всегда растёт.

Приложение получает не оригиналы картинок, а уменьшенные копии (`apps/api/src/admin/renditions.ts`): оригинал вписывается в рамку и перекодируется в PNG с палитрой на 256 цветов, файл получается в 10–20 раз легче. Формат остаётся PNG, поэтому контракт, проверки издателя и старые версии приложения не меняются. Рамки (`DELIVERY`) рассчитаны на трёхкратную плотность экрана: обложка 1024×1024, картинка слова 384×384 на ячейку атласа (атлас 2×2 — 768×768), тело маскота и слои одежды 512×768, портрет 384×384, иконка вещи 320×320. Копия делается при подготовке выпуска один раз и запоминается в `asset_renditions`, поэтому следующие выпуски её переиспользуют и версии уроков не меняются. Если файл используется в двух местах, берётся бо́льшая рамка. Оригиналы остаются в панели: их используют генерация, редактирование и предпросмотр. Когда появляется новая рамка или копии делаются впервые, уроки с картинками получают новую версию, а старые версии остаются в хранилище. Магазин (`/v1/shop`) отдаёт такие же копии. Для списков и библиотеки панель берёт превью `/v1/admin/assets/<id>/file?w=320|640`, они кэшируются в `<ADMIN_STORAGE_ROOT>/thumbs/`.

План выпуска фиксирует snapshot и базовую ревизию; если каталог сменился до нажатия «Опубликовать», план отклоняется (409), нужно подготовить новый. Откат — «Восстановить» у старой ревизии: создаётся новый выпуск с прежними пакетами, черновики в базе не меняются. После ручной публикации из CLI выполнить `pnpm admin:import`, чтобы база узнала новые сущности.

## Генерация с ИИ

Мастер на странице сета запускает фоновую работу (`generation_jobs`): число слов задаётся полем «Слов в сете» (пусто — `GENERATION_WORDS_PER_LESSON` × уроков, по умолчанию 4 на урок, минимум «уроков + 1», максимум 40; каждое слово — одна картинка и одна озвучка), модель предлагает словарь и план уроков, затем задания каждого урока (structured output по строгой JSON-схеме), сервер проверяет материал теми же правилами, что и публикация (`courseLessonSchema`, решаемость `build-word`, число заданий, разные цели уроков), после чего генерируются обложка (1536×1024 PNG), иллюстрации слов (1024×1024 PNG) и озвучка (WAV) — все файлы проходят ту же проверку, что и загрузки, и попадают в библиотеку медиа с происхождением `generated` (модель, версия промпта, промпт). Сборка создаёт уроки `<id сета>-NN` как обычные черновики. Уроки, изменённые вручную во время генерации, не перезаписываются: вариант ИИ хранится отдельно до кнопки «Применить». Публикация — обычная. Повторный запуск того же сета переиспользует готовые файлы с тем же входом и не генерирует уже существующие в языке слова.

## Клонирование сета на другой язык

На странице сета — «Клонировать на другой язык». ID нового сета собирается из названия с транслитерацией (кириллица, иврит) и случайным суффиксом, например `he-zagadochnyy-les-27eq`; его можно поправить. Клон всегда создаётся черновиком, исходный сет не меняется, обложка и описание копируются.

- **Копия как есть** — мгновенно дублирует уроки, картинки, озвучку и задания; слова, озвучку и плитки «Собери слово» затем меняют вручную в редакторе.
- **Перевести с ИИ** — фоновая работа в той же очереди, что и генерация: модель переводит словарь (текст, написание для плиток без огласовок, текст для озвучки) и правит русские тексты уроков, где упоминались слова исходного языка. Картинки (включая области атласа), ID слов, порядок и механики заданий сохраняются; заново записывается только озвучка, плитки пересобираются под новое написание. Результат — черновик «готово к проверке», публикация обычная.

## Язык интерфейса и переводы уроков

Приложение говорит на трёх языках: русском, английском и иврите (справа налево). По умолчанию выбран язык устройства, если приложение его знает, иначе русский. Ребёнок меняет его в профиле («Язык приложения»). Выбор хранится на устройстве (`lingvohero.locale`) и в аккаунте (`learner_accounts.ui_locale`). Новое устройство подхватывает язык из аккаунта, пока на нём не выбрали свой.

Тексты интерфейса лежат в `apps/mobile/src/i18n/texts/`: один файл на раздел, внутри рядом ru, en и he. Русский задаёт ключи, а пропущенный перевод ловит `tsc`. Названия квестов и трофеев переводятся по их id в `texts/catalog.ts`. Маскоты и вещи из панели переводятся в самой панели: кнопка «Перевести тексты (EN, HE)» в разделах «Маскоты» и «Магазин» ставит одну работу на всё, что не переведено или устарело, а блок «Переводы» на странице маскота или вещи правит перевод вручную. `/v1/shop` отдаёт только полные переводы (`texts` у маскота и вещи). Если перевода нет, приложение берёт встроенный из `texts/catalog.ts`, а если нет и его, показывает русский текст.

**Тексты уроков хранятся в самом уроке.** Базовые поля пакета остаются русскими, а переводы приходят оверлеем:

- `texts.en` / `texts.he` с полями `title`, `presentation`, `exercises[id].{prompt, hint}` и `words[id].translation`;
- у сета в каталоге `texts[locale].{title, description}` и `locales`;
- у ссылки на урок `titles[locale]`;
- у языка `titles[locale]`.

Слова изучаемого языка (текст, написание, плитки) не переводятся. `schemaVersion` остаётся 2, старые клиенты оверлей просто не читают.

Урок есть на языке интерфейса, только когда оверлей покрывает все его тексты. Сет есть на этом языке, когда такие все его уроки. Издатель вычисляет `locales` сам и сверяет их с пакетами. **Сет без перевода на язык интерфейса ребёнка скрыт**, и в порядке открытия сетов он не участвует. Это правило (`visibleCatalog`) одинаково применяют приложение и сервер при проверке доступа в `/sync`.

Переводы делает кнопка «Перевести тексты (EN, HE)» на странице сета. Это работа `texts` в очереди генерации: по одному вызову модели на урок, иврит без огласовок и в нейтральной по роду форме. После сборки сета мастером ИИ перевод ставится в очередь сам. Каждый перевод помнит отпечаток русского текста (`sourceHash`). Если русский текст поправили, панель и подготовка выпуска показывают «перевод устарел», а повторный запуск переведёт только такие уроки. Вручную переводы правятся на вкладке «Переводы» урока и в полях карточки сета. Добавление перевода поднимает версию урока, как любая другая правка.

Встроенный выпуск `content/seed.json` содержит переведённый лесной сет, чтобы и без сети первая тема была на всех трёх языках. Его пересобирают из опубликованного хранилища, не меняя встроенные медиа.

## Несколько изучаемых языков

Ребёнок учит сразу несколько языков. Аккаунт хранит их список (`learner_accounts.languages`) и текущий (`language`). При регистрации язык не спрашивают. После выбора маскота открывается экран «Какой язык будем учить?». Если языков больше одного, при каждом запуске приложение сначала спрашивает «Какой язык сегодня?» и только потом показывает сеты. Добавить или сменить язык можно в боковом меню (☰ в шапке или свайп от края), пункт «Языки».

Прогресс каждого языка независим: он привязан к урокам, а сеты открываются по порядку внутри языка. Монеты, опыт, звёзды и трофеи общие для всех языков. Незаконченный урок одного языка остаётся единственным: на главной другого языка видно, где он ждёт, и есть кнопка перейти туда.
