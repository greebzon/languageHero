# ЛингвоГерой

Игровое приложение для изучения английского детьми **6–9 лет**, на React Native + Expo для Android и iOS. Дизайн основан на материалах `../stitch_`, персонаж — лисёнок Тим.

Главная «Миры» переделана по `../main_s`: карточки сетов, реальный прогресс и звёзды, быстрый старт/продолжение, отдельная карта уроков. Сеты открываются последовательно внутри языка; полученный доступ сохраняется при обновлениях каталога. «Подводный мир» и «Космос» пока являются анонсами «Скоро» с предоставленными изображениями. Контентом управляет [админ-панель](#админ-панель); её [план](docs/ADMIN_IMPLEMENTATION_PLAN.md) реализован в части этапов A–D (ручное редактирование, публикация, генерация с ИИ).

Реализована первая тема: **пять уроков про животных, 23 задания и три механики** — послушай и выбери, найди пары, собери слово. Есть карта, словарь, награды и профиль, обычная/замедленная озвучка, подсказки и повторение ошибок в конце урока. Позиция, частичный ответ и настройки сохраняются на устройстве; старый демо-прогресс переносится автоматически. Повторное прохождение и новая версия урока не удваивают монеты.

Каталог языков/курсов и версионированные уроки доступны через API. Новый урок на поддерживаемых механиках появляется после публикации данных и обновления каталога, без пересборки приложения. Начатый урок сохраняет свою версию. Начальная тема и медиа также включены в приложение; перед входом в урок его файлы загружаются целиком. При потере связи появляется уведомление, а открытый урок продолжает работать. Аккаунты, серверная синхронизация и автоматическая предзагрузка трёх следующих уроков ещё предстоят по [плану](docs/ROADMAP.md).

## Запуск

Нужны Node.js **22.13+** и pnpm **11.22.0**. Команды выполняются из корня этого проекта.

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Открыть проект в Expo Go, совместимом с SDK 57: отсканировать QR-код на телефоне в одной сети с компьютером. Для Android-эмулятора с установленным SDK нажать `a` в терминале Expo. На Windows запуск iOS проверяется на физическом iPhone через Expo Go; локальный iOS-симулятор требует macOS.

Для быстрого просмотра тех же экранов в браузере:

```powershell
pnpm dev:web
```

Обычный адрес — `http://localhost:8081`. Веб-предпросмотр служит для разработки; полноценная автономная загрузка веб-страницы после отключения сети не реализована. Expo Go также требует сервер для первоначальной загрузки JavaScript. Самостоятельные подписанные APK/IPA относятся к этапу тестовых сборок.

Сервер каталога запускается в отдельном терминале:

```powershell
pnpm dev:api
```

Проверка: `GET http://127.0.0.1:3001/health`, каталог: `GET http://127.0.0.1:3001/v1/catalog?schemaVersion=2`. Первый выпуск уже опубликован в `content/store`. Без API остаются встроенная тема и сохранённые пакеты.

По умолчанию приложение обращается к `localhost:3001`, Android-эмулятор — к `10.0.2.2:3001`. Для телефона задать `EXPO_PUBLIC_API_URL=http://<локальный-IP-компьютера>:3001` в `apps/mobile/.env`, а `HOST=0.0.0.0` в `apps/api/.env`, затем перезапустить Expo/API. Для публичного сервера использовать HTTPS.

Добавление языков, заданий и медиа описано в [инструкции публикации](docs/CONTENT.md). Команда `pnpm content:publish <файл-выпуска.json>` публикует выпуск из JSON без панели; после неё выполнить `pnpm admin:import`.

## Админ-панель

Редакторская панель (`apps/admin`) работает поверх того же API и PostgreSQL в Docker. Первый запуск:

```powershell
pnpm db:up                     # PostgreSQL 17 на порту 5433 (docker compose)
pnpm db:migrate                # миграции из apps/api/drizzle
pnpm admin:bootstrap admin     # первый администратор; пароль спросит в консоли
pnpm admin:import              # текущий content/store → база (повторный запуск ничего не дублирует)
pnpm dev:admin                 # http://localhost:5173/admin/ (API должен быть запущен: pnpm dev:api)
```

В панели создаются языки, сеты, уроки трёх механик и медиа; урок можно пройти как ребёнок. «Выпуски» показывают план и список изменений, публикация — отдельной кнопкой; после неё в приложении нажать «Обновить». Черновики не попадают в публичный API, опубликованные версии уроков не меняются. Подробности — в [apps/admin/README.md](apps/admin/README.md) и ADR [0001](docs/adr/0001-admin-storage.md), [0002](docs/adr/0002-generation-queue.md). Без `DATABASE_URL` API работает как раньше, только без `/v1/admin`.

Генерация сета с ИИ («Черновик с ИИ» на странице сета: язык → тема → общее число заданий) выполняется отдельным процессом:

```powershell
pnpm dev:worker                # очередь в PostgreSQL; ключ OPENAI_API_KEY в apps/api/.env
```

Worker проходит стадии план → тексты → проверка → обложка → иллюстрации → озвучка → сборка, показывает прогресс и ошибки по шагам, повторяет временные сбои сам, а постоянные оставляет для кнопки «Повторить шаг». Результат — черновик «готово к проверке»; ничего не публикуется автоматически. `GENERATION_PROVIDER=fake` даёт весь сценарий без ключа и расходов (так работают автотесты). Лимит стоимости работы — `GENERATION_COST_LIMIT_USD`; число слов — поле «Слов в сете» в мастере или норма `GENERATION_WORDS_PER_LESSON` (по умолчанию 4 на урок).

## Аккаунты учеников

Один аккаунт принадлежит одному ребёнку, у каждого ребёнка своя почта. Родитель не участвует в приложении; семейные аккаунты и несколько детских профилей в одном аккаунте не предусмотрены.

Приложение требует входа: ребёнок вводит свою почту, получает 5-значный код и подтверждает его; при первом входе выдаётся резервный код на случай потери почты. Прогресс хранится на сервере: каждая попытка урока отправляется как последовательность ответов и **проигрывается заново на сервере** тем же движком, поэтому звёзды и награды нельзя подделать; на устройстве остаётся локальная копия, а при потере связи урок продолжается и синхронизируется позже.

«Сокровищница» (ежедневные квесты, трофеи, монеты) и магазин тоже считаются на сервере: журнал активности собирается из проверенных попыток, а каждая награда и покупка — строка в журнале монет (`learner_ledger`). Приложение лишь показывает журнал и перед получением награды или покупкой отправляет на сервер несохранённые уроки. «Сегодня» для квестов определяется по часовому поясу устройства (`tzOffset`).

Для локальной разработки в `apps/api/.env` нужны `ACCOUNT_SECRET` (случайная строка 32+ символа) и режим почты `ACCOUNT_MAIL_MODE=file` — тогда письма не отправляются, а код лежит в `.data/account-mail/<challengeId>.json`. Для настоящей почты — `ACCOUNT_MAIL_MODE=smtp` и `SMTP_*`. `ACCOUNT_ORIGINS` — список адресов веб-версии, которым разрешены cookie-запросы; Expo Go и нативные сборки используют токен и в список не входят. Без `ACCOUNT_SECRET` маршруты `/v1/account` отключены, и приложение не сможет войти.

## Уровни и друзья

Галерея «Мои друзья» доступна с главной, из профиля и меню. Тим открыт с уровня 1, Луна — 3, Балу — 5, Умка — 8; пороги настраиваются в панели. Первый урок повышает уровень до 2. Открытия сохраняются навсегда, активный спутник выбирается один на аккаунт. Перед запуском обновлённого API применить `pnpm db:migrate`. Подробные правила — [уровни и маскоты](docs/LEVELS_AND_MASCOTS.md).

## Маскоты и магазин в панели

Разделы «Маскоты» и «Магазин» панели управляют спутниками и гардеробом. Новый маскот описывается текстом (или загружается PNG в полный рост) — сервер сам рисует тело на прозрачном фоне, круглый портрет, размечает зоны (голова, глаза, торс, спина, место для спутника) и примеряет на него каждую вещь магазина. Новая вещь — описание или PNG, тип (куда надевается), категория (обычная / магическая / легендарная) и цена; иконка и примерка на всех маскотов рисуются автоматически. В приложение попадает только опубликованное (`GET /v1/shop`); пока ничего не опубликовано, приложение показывает встроенных четырёх спутников и пять вещей (без примерочных слоёв — вещи видны только в списке). Купленные вещи ребёнок надевает в «Примерочной» (кнопка на вкладке «Награды» и в профиле, «Надеть» прямо в магазине): по одной вещи на место, непосещённые можно примерить перед покупкой; образ хранится в аккаунте и одинаков на всех устройствах. Встроенных можно завести в панель командой `pnpm admin:import-wardrobe` (с `--generate` сразу запустятся работы по отрисовке).

## Настройки

Ключ OpenAI нужен **только для генерации с ИИ** в панели: скопировать `apps/api/.env.example` в `apps/api/.env` и заполнить `OPENAI_API_KEY`; модели и лимиты — там же (`OPENAI_*`, `GENERATION_*`). Серверный ключ никогда не должен попадать в переменные `EXPO_PUBLIC_*`. Файлы `.env` исключены из Git; мобильный `.env.example` содержит только публичный адрес API.

Настройка звука находится в профиле. Если звук выключен, кнопка прослушивания в уроке предлагает включить его. Нажатие крестика в уроке сохраняет позицию и позволяет вернуться к ней с карты.

## Проверки

```powershell
pnpm typecheck
pnpm test
pnpm format:check
pnpm --filter @lingvohero/mobile exec expo install --check
pnpm --filter @lingvohero/mobile exec expo export --platform all
```

Браузерные проверки запускаются через Playwright:

```powershell
pnpm exec playwright install chromium
pnpm test:e2e
```

Тесты панели с базой (`pnpm test:admin`) и сценарии «сет из панели → приложение» и «сгенерированный сет → приложение» в `pnpm test:e2e` требуют `DATABASE_URL_TEST` в `apps/api/.env` и запущенный `pnpm db:up`; каждый запуск создаёт и удаляет отдельную базу. Без переменной они пропускаются.

Для использования уже установленного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Тесты используют отдельные порты 8082/3002 и копию каталога в `.cache/e2e-content`; рабочий каталог не изменяется. Проверяются пять уроков, все механики, частичные ответы после перезагрузки, повторение ошибок, озвучка без сети, миграция, награды и настоящая публикация нового пакета/медиа при работающем приложении. Скриншоты появляются в `test-results/`.

Нативный smoke-тест: при запущенном Metro и Android-эмуляторе с Expo Go выполнить `python scripts/android-smoke.py --serial emulator-5554 --course`. Требуется `ANDROID_HOME`; начальный экран — карта без незавершённого урока. Скрипт проходит все пять уроков и пишет снимки в `.cache/android-smoke`; без `--course` проверяет только первый. Он работает только с эмулятором и не взаимодействует с подключёнными физическими телефонами. iOS-сборка ресурсов не заменяет проверку на iPhone.

## Структура

| Путь                      | Содержимое                                      |
| ------------------------- | ----------------------------------------------- |
| `apps/mobile`             | Мобильное приложение, экраны, локальные ресурсы |
| `apps/api`                | API каталога, пакетов, медиа и публикация       |
| `apps/admin`              | Веб-панель редактора (React + Vite)             |
| `packages/contracts`      | Проверяемые схемы каталога, уроков и прогресса  |
| `packages/learning-core`  | Правила урока, сохранения и наград, тесты       |
| `content/assets-manifest` | Происхождение графики, аудио и шрифтов          |
| `content/store`           | Выпущенные каталоги, версии уроков и медиа      |
| `tests/e2e`               | Проверки пользовательского пути                 |

Полная [архитектура](docs/ARCHITECTURE.md) описывает целевую систему. В [плане реализации](docs/ROADMAP.md) отмечено текущее состояние. Следующие этапы — бэкапы и восстановление (E), затем аккаунты, серверный прогресс и предзагрузка следующих уроков.
